# Linux Kernel Rust Coding Manual & Agent Directives

This document defines the rules for writing Rust code in the Linux Kernel ("Rust-for-Linux"). **It is strictly enforced for AI Agents to ensure safety and soundness.**

## 1. Core Directives for Agents

**Objective:** Write safe, zero-cost abstractions that interface seamlessly with the C kernel.

### 1.1 The "No Panic" Absolute Rule
*   **Rule:** The kernel cannot panic. It must handle all errors gracefully.
*   **Forbidden:** `unwrap()`, `expect()`, `panic!()`, or any operation that might panic on failure (like slice indexing without checking bounds, though iterators are preferred).
*   **Mandatory:** Return `Result<T, Error>`.
*   **Agent Check:** grep your generated code for `unwrap()`. If found, delete it and handle the error.

### 1.2 The "Explicit Safety" Rule
*   **Rule:** Every `unsafe` block must be documented.
*   **Format:**
    ```rust
    // SAFETY: Explain WHY this is safe. E.g., "The pointer is guaranteed valid by the caller and not NULL."
    unsafe { bindings::some_c_func(ptr) };
    ```
*   **Agent Logic:** If you cannot explain why it is safe, you cannot write the code.

## 2. Architecture: The Rust Subsystem

*   **`rust/kernel/`**: The safe API surface. **Prefer using this over raw bindings.**
    *   `kernel::sync`: Mutexes, Spinlocks.
    *   `kernel::error`: Error handling types.
    *   `kernel::driver`: Driver abstractions.
*   **`rust/bindings/`**: Raw C FFI generated by bindgen. Use only when necessary.

## 3. Best Practices & Patterns

### 3.1 Error Handling Idioms
**Directive:** Map C error codes to Rust `Result`.
*   **Pattern:**
    ```rust
    fn do_something() -> Result {
        let ret = unsafe { bindings::c_function() };
        if ret < 0 {
            return Err(Error::from_errno(ret));
        }
        Ok(())
    }
    ```

### 3.2 Pinned Initialization (`PinInit`)
**Context:** Kernel structures (mutexes, waitqueues) rely on their memory address not changing (they are self-referential).
**Problem:** Rust moves values by default.
**Solution:** Use the `PinInit` system.
*   **Agent Directive:** When initializing a struct containing a lock, use `try_pin_init!`.
    ```rust
    impl MyDriver {
        fn new() -> impl PinInit<Self, Error> {
            try_pin_init!(Self {
                lock: new_spinlock((), "MyDriver::lock"),
                data: 0,
            })
        }
    }
    ```

### 3.3 The `container_of!` Macro
**Directive:** Use the safe Rust version of this classic C macro.
*   **Usage:** To downcast from a field pointer back to the containing struct.
*   **Safety:** The macro handles the pointer arithmetic safely (or as safely as possible).

### 3.4 Opaque Types (`Opaque<T>`)
**Context:** Interfacing with C structs that act as opaque handles.
**Directive:** Wrap C structs in `Opaque<T>` to prevent accidental direct access to their fields from safe Rust.
*   **Reason:** C structs might have internal invariants or bit-fields that Rust's ABI doesn't match perfectly.

## 4. Concurrency & Sync

### 4.1 Locking
**Directive:** Use `kernel::sync::Mutex` or `SpinLock`.
*   **Pattern:** RAII locking.
    ```rust
    let guard = self.lock.lock();
    // Access data via guard
    // Lock released automatically here
    ```

### 4.2 Allocation
**Directive:** Use `KBox` (Kernel Box).
*   **Rule:** Allocation is fallible. You must provide flags (e.g., `GFP_KERNEL`).
    ```rust
    let b = KBox::new(MyData::default(), GFP_KERNEL)?;
    ```

## 5. Agent Workflow for Rust

1.  **Check Safe Abstractions:** Before calling `unsafe { bindings::foo() }`, check if `rust/kernel/foo.rs` exists.
2.  **Verify Memory Safety:** Ensure that no references outlive their referents (lifetimes).
3.  **Document Safety:** Write the `// SAFETY:` comment *before* writing the unsafe block.
4.  **Review Panics:** Ensure no code path can trigger a panic.
